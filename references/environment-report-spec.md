# 编译环境说明 PDF 规范

仅在环境首次创建或状态实际改变时读取本规范。PDF 是环境状态的版本化快照，不是普通运行日志。

## 存放与命名

将 PDF 直接保存在项目根目录的 `compile-environment/` 中，与唯一活动环境 `runtime/` 同级：

```text
compile-environment/
|-- runtime/
|-- 编译环境说明_v1.0.0_初始创建.pdf
`-- 编译环境说明_v1.0.1_更新测试依赖.pdf
```

使用 `编译环境说明_vMAJOR.MINOR.PATCH_简要修改内容.pdf`。版本号必须递增，摘要应准确描述本次变化。不得覆盖、删除或改名历史版本。

## 必含内容

1. 项目名称与报告生成时间（注明时区）。
2. 文档版本和本次修改摘要。
3. 唯一活动环境的项目相对路径与环境后端，例如 Conda prefix、`venv`、原生工具链或容器。
4. 操作系统类别、架构，以及解释器、编译器、SDK、包管理器的精确版本。
5. 直接依赖及其锁定版本；依赖较多时可附完整清单，并在正文突出主要依赖。
6. 创建、激活、安装、构建、测试和运行命令。命令使用项目相对路径或占位符，不写私人用户名路径。
7. 影响运行的环境变量名称及用途。只记录名称、安全示例或值来源，绝不记录秘密值。
8. 本次环境变更前后对比，以及上一版 PDF 文件名；首次创建写明“无上一版本”。
9. 实际执行的验证命令、结果和验证时间。
10. 已知限制、平台假设，以及从零重建环境的步骤。

## 生成与验收

- 使用当前可用且可信的 PDF 生成能力；生成工具不得向项目再引入第二个运行环境。
- PDF 生成所需依赖若必须加入项目环境，本身也属于环境变更，应包含在同一版本报告中。
- 生成后渲染或打开检查：页面完整、中文可读、命令不被裁切、长依赖清单可分页。
- 按语义化版本识别最新报告；文件修改时间仅作辅助，不能替代版本号。
- 如果报告内容有误，保留错误版本并生成递增的新版本；不得覆盖旧文件。

## 安全与隐私

- 不写入密码、访问令牌、API 密钥、私钥、Cookie、连接串秘密或完整 `.env` 内容。
- 不写入与复现无关的用户名、邮箱、设备名、家庭目录或本机绝对路径。
- 必须说明某项秘密配置时，只记录变量名、用途和“由用户安全提供”等来源描述。
